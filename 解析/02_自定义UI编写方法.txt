EXPAS 经验扩展插件系统 —— 自定义 UI（HUD 布局）编写方法
正式 DLL: EXPAS.NP.dll      插件版本: v2.0.0-beta
整理日期: 2026-09-29
================================================================================

【0. 一句话概览】

  EXPAS 的 HUD 有两套渲染来源，按下面的优先级走：

    ① 玩家在 SSS 面板里选中了**来自文件的自定义布局**（layouts\ 下的 .txt / .js）
       → 用那份布局文件渲染（该玩家的 HUD 完全由布局决定）
    ② 其它所有情况（没选 / 选 default / 布局文件不存在 / 归属不匹配）
       → 用 config.yml 里的文本模板（hud_line1~4、hud_level1~2、custom_lines）

  ★ 布局是"玩家可选"的，但**不是所有人都能看到这个选项**：
     布局文件的 owner 与玩家 Steam64 匹配，或玩家在 custom_ui_whitelist 里，
     他的面板中才会出现「自定义 UI」下拉；其他人**整项不显示**，固定使用默认布局。

--------------------------------------------------------------------------------
【1. 目录位置】
--------------------------------------------------------------------------------
  %APPDATA%\SCP Secret Laboratory\LabAPI\configs\<服务器端口>\EXPAS\layouts\

  例:  C:\Users\<你>\AppData\Roaming\SCP Secret Laboratory\LabAPI\configs\7777\EXPAS\layouts\

  支持的扩展名:  .txt  和  .js
  编码要求:      UTF-8（推荐**无 BOM**）
  文件名:        就是布局的 key（不含扩展名）。例如 示例玩家.txt → key = 示例玩家
  内置默认布局:  key = default（永远存在，玩家总能看到）
  首次运行会自动生成两份样板:  default.txt、example.txt

--------------------------------------------------------------------------------
【2. .txt 布局文件格式】
--------------------------------------------------------------------------------

2.1 两种行：注释 / 正文

  注释行      以 # 开头 → 整行忽略
              行内注释  在文本中标 " # "（# 前面必须是空白）→ # 之后忽略
  正文行      用竖线 | 分段，格式:

                 <类型>|<对齐>|<垂直偏移>|<文本>

              各段含义:

     <类型>      必填，只能是这 5 种（写别的会被整行忽略）:
                   row     主块（贴在屏幕最下方，最常用）
                   level   等级块（右下角那块等级/经验）
                   kill    击杀确认块（只在"击杀提示期"内显示）
                   fold    HUD 折叠模式下显示的行（代替 config 的 hud_collapsed_line）
                   custom  配置自定义行插入点（把 config.yml 的 custom_lines 插到这里）
     <对齐>      可选。left / l / 左 = 0    center / c / 中 / 居中 = 1    right / r / 右 = 2
                   也可直接写 0 / 1 / 2。缺省 = 1（居中）
     <垂直偏移>  可选，整数像素。**数值越大越靠上**。
                   同一块内按偏移从大到小自上而下排列（偏移最大的在最上面）。
                   整块的竖直位置 = 块内最大偏移（会按玩家分辨率档位自动缩放）。
                   缺省 = 0
     <文本>      必填（custom 类型可为空）。支持全部占位符（见第 5 节），
                   也支持 TMP 富文本标签，如 <color=#FF0000>…</color>、<size=120%>…</size>
                   文本里可以再写 |（第 3 段之后的所有内容会被合并回文本）

2.2 元信息行

  写法:   name = 显示名
  作用:   这个布局在玩家面板下拉里显示的名字（不写就用文件名 key）。
  注意:   只有当一行里**没有 |** 且含 = 时才被当作元信息行。
          owner 单独处理（见第 3 节）。

2.3 最小可用示例（layouts\示例玩家.txt）

      # EXPAS HUD 布局示例 —— UTF-8
      name = 示例专用布局
      owner = 76561198000000000

      row|center|-0|#1 欢迎 {name} 进入 {server}
      row|center|-32|#2 已游玩 {days} 天   当前 {tz} {clock}
      row|center|-64|#3 本回合伤害 {roundDmg}   总伤害 {totalDmg}
      row|center|-96|EXPAS v{version}{icons}

      level|right|40|您当前有 {level} 级
      level|right|16|距离下一次升级还差 {expNeed} 经验

2.4 五种类行的完整示例

      # 主块（最常用）
      row|center|-0|本回合伤害 {roundDmg}

      # 等级块（右下角）
      level|right|40|Lv.{level}  经验 {exp}/{expNeed}

      # 击杀确认块（只在击杀后 KillNoticeSeconds 秒内显示）
      kill|center|120|<color=#FFD700>已击杀 {killRole}</color>
      kill|center|96|占比 {killShare}%   伤害 {killDamage}   积分 +{killPoints}

      # 折叠模式（玩家在面板里把「HUD 折叠」切成"折叠"时用这几行）
      fold|center|-0|[EXPAS] Lv.{level}  积分 {points}  伤害 {totalDmg}

      # 配置自定义行插入点（把 config.yml 的 custom_lines 全部插到这里）
      custom|center|160|

      # 行内注释演示
      row|left|60|这是正文   # 这半句会被忽略

2.5 没有写 kill 行时会怎样

  布局里**完全不含** kill| 行 → 保持旧行为: 系统把"定格好的击杀块"
  （来自 config.yml 的 kill_line1~3）追加到主块下方。
  一旦你写了任意一行 kill|，就**完全由布局决定**击杀块内容。

2.6 没有写 fold 行时会怎样

  玩家切到"折叠"模式时，如果布局里没有 fold| 行 → 用 config.yml 的
  hud_collapsed_line 模板；有 fold| 行则用布局里的那几行（击杀提示照旧追加）。

【3. 归属识别（这份布局属于谁）】
--------------------------------------------------------------------------------
  两种"双保险"写法，任选其一；两个都写也可以（文件内声明优先）:

    ① 文件名前缀 = Steam64（17 位数字）
         76561198000000000.txt
         76561198000000000.js

    ② 文件内声明 owner（首行注释或变量声明都认）
         # owner = 76561198000000000
         // owner = 76561198000000000
         owner = 76561198000000000
         const owner = "76561198000000000";

  归属匹配规则:
    · 纯数字 76561198000000000 与 76561198000000000@steam 视为等价
    · 只有 owner 匹配（或玩家在白名单里）的玩家，才能在面板里看到并使用这份布局
    · 没有 owner、又不在白名单里的布局文件 → 加载得出，但**谁都用不了**
      （除非把玩家加进 custom_ui_whitelist）

  ★ 想让某个玩家用上他的布局，最短路径:
       a. 把布局文件命名为 <他的Steam64>.txt 放进 layouts\
       b. 服务器里执行  EXPAS layout reload
       c. 他打开 ESC → 设置 → 服务器设置 → EXPAS，在「自定义 UI」里选它

【4. .js 布局文件怎么写】
--------------------------------------------------------------------------------
  ★ 重要前提: 游戏和服务器**不会执行任何 JS 代码**。
    .js 在这里只被当作**文本**读取 —— 解析器只从里面提取:
       · 双引号 / 单引号里的字符串
       · owner / name 的赋值
    其余 JS 语法（函数、循环、import、export…）会被忽略。

  所以 .js 就是"给 txt 内容套一层 JS 外壳"，方便和前端/网页工具对接。
  两种等效写法:

  写法 A —— 一行一个字符串（推荐，最直观）:

      // owner = 76561198000000000
      const name = "示例专用布局";
      const rows = [
        "row|center|-0|#1 欢迎 {name} 进入 {server}",
        "row|center|-32|#2 已游玩 {days} 天",
        "row|center|-64|#3 本回合伤害 {roundDmg}",
        "level|right|40|您当前有 {level} 级",
        "level|right|16|距离下一次升级还差 {expNeed} 经验"
      ];

  写法 B —— 无引号的直写（剥掉 JS 噪音后保留 owner/name 直写）:

      // owner = 76561198000000000
      name = 示例专用布局
      row|center|-0|#1 欢迎 {name} 进入 {server}
      row|center|-32|#2 已游玩 {days} 天

  解析规则细节（照这个写就不会踩坑）:
     · 行首 // 注释: 只有含 owner 的那行会保留（用于归属识别），其余丢弃
     · 一个数组行里放多个字符串 → 会被拆成多行处理
     · const name = "…" / const owner = "…" → 当作元信息
       正文里的 {name} 占位符**不会**被误认成 name 赋值
     · 字符串末尾的 , 和 ; 会自动去掉
     · 一行里同时出现 owner 和 17 位数字 → 直接认定为归属

  也可以直接用 .txt 后缀写同样的内容（.txt 不需要引号，更省事）。

--------------------------------------------------------------------------------
【5. 全部占位符（布局文本里随便用）】
--------------------------------------------------------------------------------
  {name}       {server}      {days}        {hours}       {tz}         {clock}
  {playtime}   {roundDmg}    {roleDmg}     {totalDmg}    {totalExp}   {level}
  {exp}        {expNeed}     {kills}       {deaths}      {version}    {icons}
  {mvpName}    {mvpDamage}   {mvpLevel}    {topList}
  {points}     {roundPoints} {killName}    {killDamage}  {killShare}  {killPoints}
  {roundTime}  {aliveCount}  {tps}         {scpCount}    {roundId}
  {killRole}      最近一次击杀的角色（RoleTypeId 名，例 NtfSergeant / Scp173）
  {killRoleKind}  该角色类型: 人形 / SCP / 人机 / 其它
  {aspect}        屏幕宽高比标签（16:9 / 16:10 / 21:9 / 4:3 / 其它(x.xx)）

  富文本标签可以直接用（TextMeshPro 语法）:
    <color=#FFD700>金色文字</color>
    <size=120%>放大</size>
    <b>加粗</b>   <i>斜体</i>
    <voffset=20>这一行单独上移</voffset>

【6. 白名单（custom_ui_whitelist，兼容/覆盖用）】
--------------------------------------------------------------------------------
  正常情况下**不需要**白名单 —— 布局文件的 owner 已经决定归属。
  白名单的作用是"兼容覆盖": 名单里的玩家可以看/用**全部**布局。

  config.yml:
      custom_ui_whitelist: []

  指令维护:
      EXPAS whitelist list
      EXPAS whitelist add 76561198000000000
      EXPAS whitelist remove 76561198000000000

  写法: 纯数字 或 7656119…@steam 等价；填 "*" = 放开给所有人（仅测试用）。

【7. 玩家自己在面板里能调什么】
--------------------------------------------------------------------------------
  路径: ESC → 设置 → 服务器设置 → EXPAS
  （所有设置按 Steam64 单独记住，每个玩家的 HUD 互不干涉）

    「自定义 UI」       选中一份布局（只有归属匹配/白名单玩家才看得到这一项）
     HUD 开关           开 / 关（关掉后你自己不再显示 EXPAS HUD）
     字号               40% .. 160%（100% = 游戏默认），步进 1
     屏幕缩放           50% .. 150%（与字号相乘）
     整体缩放           50% .. 200%（在"字号×屏幕缩放"之外再乘一次） v1.6+
     行距               60% .. 140%（小于 100 更紧凑）
     垂直位置           -200 .. 200 像素（负=整体上移，正=整体下移）
     水平对齐           左 / 居中 / 右
     等级块对齐         左 / 居中 / 右 / 跟随上面
     HUD 折叠           展开 / 折叠（折叠时只显示一行，可用布局的 fold| 行自定义）
     屏幕分辨率         16 档: 自动检测 / 640x480 / 800x600 / 1024x768 / 1280x720 /
                        1280x800 / 1366x768 / 1440x900 / 1600x900 / 1680x1050 /
                        1920x1080 / 1920x1200 / 2560x1080 / 2560x1440 / 3440x1440 /
                        3840x2160(4K)
     重置本机 HUD 设置  一键回到"跟随服务器配置"

  另外面板里还有两个折叠文本区（默认收起）:
     · 「EXPAS 我的数据」  经验/等级/伤害/时长等
     · 「EXPAS 击杀与积分」 独立的击杀与积分记录区（config: kill_feed_panel）

  ★ 分辨率说明: 服务端读不到玩家的像素分辨率，只能读到宽高比。
    「自动检测」按宽高比给倍率；倍率 = sqrt(1920*1080 / (宽*高))，夹在 [0.6, 1.6]。
    布局里 <垂直偏移> 与字号都会乘上这个倍率 —— 所以同一份布局在 4K 与 1080p
    上的观感是一致的。

【8. 生效流程与自检】
--------------------------------------------------------------------------------
  改布局文件后:
      EXPAS layout reload          重扫目录并给在线玩家重发面板（**不需要重启服务器**）
      EXPAS layout list            确认你的布局被载入: key / 显示名 / 排数 / 是否来自文件
      EXPAS layout info <玩家ID>    确认该玩家的"自定义 UI 选项 / 存储的布局 / 实际生效"

  服务器启动日志里会逐份打印:
      [EXPAS] 布局已载入: 76561198000000000 (测试布局(示例玩家)) 主块 3 / 等级块 2 / 击杀 1 /
              折叠 1 / 自定义 0 排  归属 76561198000000000@steam ← …\layouts\76561198000000000.js
      [EXPAS] 布局共 3 套: default, example, 76561198000000000 (目录 …)

  常见问题速查:
    · 玩家面板里看不到「自定义 UI」
        → 布局 owner 不是他，且他不在白名单；或该玩家名下只有 default 一份可选布局
          （只有一个选项时整项不显示）
    · 选了布局但不生效
        → 归属不匹配；执行 EXPAS layout info <玩家ID> 看"实际生效"是不是 default
    · 布局文件被忽略并 Warn("布局文件不可用")
        → 没有合法的 row| / level| 行；或文件编码不是 UTF-8（写坏中文）
    · 文本改了但没变
        → 先 EXPAS layout reload；若该玩家用的是 config.yml 模板而不是布局文件，
          要改的是 config.yml / EXPAS line / EXPAS setcfg
    · 中文乱码
        → 文件存成 UTF-8 无 BOM（记事本另存为时选"UTF-8"）

【9. 内置默认布局（= 首次生成的 layouts\default.txt）】
--------------------------------------------------------------------------------
      # EXPAS HUD 布局文件(必须 UTF-8)
      name = 默认布局
      # 主块: 默认贴在屏幕最下方居中, 每排自上而下叠加
      # 格式: row|<left|center|right>|<垂直偏移px>|<文本(支持全部占位符)>
      row|center|-0|#1 欢迎 {name} 进入到 {server}
      row|center|-32|#2 当前已经游玩了 {days} 天  当前时间段是 {tz} {clock}  您准确的游玩时间是 {playtime}
      row|center|-64|#3 当前回合已造成 {roundDmg}  当前使用的角色已造成 {roleDmg}  总伤害为 {totalDmg}
      row|center|-96|#4 EXPAS v{version}{icons}
      # 等级块: 默认右下方, 且比主块再往上一点
      level|right|40|您当前有 {level} 级
      level|right|16|距离下一次升级还差 {expNeed} 经验
