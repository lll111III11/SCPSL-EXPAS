【0. 是什么、什么时候响】

  回合结束时，系统找出**本回合造成伤害第一名**的玩家，
  用他的 Steam64 去检索  mvp_music\  目录下的 JS/TXT 文件；
  匹配到就按文件里填写的路径播放对应的音频（全服可闻）。

  ★ 音乐盒与自定义 UI 是**两套完全独立**的东西:
        自定义 UI    →  layouts\     目录（布局 .txt / .js）
        第一名音乐盒 →  mvp_music\   目录（音乐盒 .js / .txt + 音频文件）
    两个目录各自扫描，互不影响。

  ★ **不生成任何假人**。播放用"隐藏音箱"（远处高空、非空间化的 SpeakerToy），
    玩家列表里不会多出任何条目，也不会出现等级前缀之类的东西。

--------------------------------------------------------------------------------
【1. 目录位置】
--------------------------------------------------------------------------------
  %APPDATA%\SCP Secret Laboratory\LabAPI\configs\<服务器端口>\EXPAS\mvp_music\

  例:  C:\Users\<你>\AppData\Roaming\SCP Secret Laboratory\LabAPI\configs\7777\EXPAS\mvp_music\

  这个目录里放两样东西:
     ① 一份声明文件:  <Steam64>.js    （或 .txt，两者等价）
     ② 对应的音频文件:  xxx.wav / xxx.ogg / xxx.mp3 …

  编码要求: UTF-8（推荐无 BOM）

--------------------------------------------------------------------------------
【2. 声明文件怎么写】
--------------------------------------------------------------------------------
  只需要两行信息: 谁的（owner） + 放哪首（audio）。

  2.1 .js 写法（推荐）

      // owner = 76561198000000000
      const owner = "76561198000000000";
      const audio = "示例开场曲.wav";

  2.2 .txt 写法（完全等价，不用引号）

      # owner = 76561198000000000
      owner = 76561198000000000
      audio = 示例开场曲.wav

  2.3 owner 的两种给法（可任选，也可都写）

    ① 文件名前缀 = Steam64（17 位数字）
         76561198000000000.js
       —— 文件名里的 17 位数字**优先**，最省事，推荐直接用这个。

    ② 文件里声明 owner（三种前缀都认）
         // owner = 76561198000000000
         # owner = 76561198000000000
         const owner = "76561198000000000";
       —— 纯数字与 7656119…@steam 等价。

  2.4 audio 的键名

     下面这些键名**都认**（大小写不敏感，允许 const / let / var 前缀）:
         audio    music    file    path    wav

     值可以带引号也可以不带，末尾的 ; 和 , 会自动去掉:
         const audio = "示例开场曲.wav";
         audio = 示例开场曲.wav
         music = "D:\音乐\开场.mp3"          ← 绝对路径也可以
         path  = "https://…"                ← 不支持网络地址，仅本地文件

  2.5 解析规则细节（照这个写就不会踩坑）

     · 服务器**不会执行任何 JS 代码**，只按文本读取引号里的字符串和 owner/name 赋值
     · 一行里同时出现 owner 和 17 位数字 → 直接认定为归属
     · 缺 owner 或缺 audio → 该文件被跳过，日志 Warn:
         [EXPAS] 音乐盒 JS 不可用(缺 owner 或 缺 audio=): …
     · 同一个 Steam64 出现多份声明 → 后扫描到的覆盖前者（建议一个 Steam64 只留一份）

--------------------------------------------------------------------------------
【3. 音频怎么放、路径怎么找】
--------------------------------------------------------------------------------
  推荐: 把音频和声明文件放**同一个目录**（mvp_music\），audio 里只写文件名。

  路径解析顺序（按序查找，命中即用）:
      ① audio 写的是绝对路径且文件存在 → 直接用
      ② mvp_music\ <audio>        ← 音频放本目录（推荐）
      ③ audio\     <audio>        ← 也可以放到 EXPAS\audio\ 里复用
      ④ 都不存在 → 视为"音频缺失"，回合结束时会 Warn 并跳过

  支持的格式（原生解码器全部支持）:
      wav  ogg  mp3  m4a  aac  mp4  flac  wma  opus  aiff  aif  wv  ape  mka  webm

  音频要求:
      · 采样率任意（会自动重采样成 48000Hz）
      · 单声道 / 立体声都行（会自动混成单声道）
      · 建议 10~60 秒 —— 太长会影响回合节奏
      · 文件名避免特殊符号  \ / : * ? " < > |   （路径分隔除外）
      · **WAV 建议 PCM 16bit** —— 这是唯一走内置快速解码的格式，最省资源

  解码器: 内嵌自建原生 DLL 解码器（EXPAS.AudioCodec.dll + ffmpeg 共享库，
  由 ffmpeg n9.0.1 源码编译而来），启动时释放到 EXPAS\bin\native\，
  **不需要任何 exe**、不需要额外安装 ffmpeg。

【4. 完整示例】
--------------------------------------------------------------------------------

  目录:
      configs\7777\EXPAS\mvp_music\
          76561198000000000.js      ← 声明
          示例开场曲.wav             ← 音频

  76561198000000000.js:
      // owner = 76561198000000000
      const owner = "76561198000000000";
      const audio = "示例开场曲.wav";

  回合结束 → 伤害第一名是 76561198000000000 →
      日志: [EXPAS] 第一名音乐盒触发: 76561198000000000@steam → 示例开场曲.wav

    （每次触发都会重新扫描目录）。

【5. 开关与相关配置】
--------------------------------------------------------------------------------
  config.yml:

      mvp_music_enabled: true
          音乐盒总开关。回合结束时检测伤害第一名并检索 mvp_music\*.js。

      mvp_music_players: []
          【可选/兼容】老式映射表，每行写作  Steam64|音频文件名或路径。
          一般**不用**，请改用 mvp_music\<Steam64>.js 声明方式；留空即可。

      audio_playback_plan: 1
          音频播放方案:  0 = 关闭   1 = 隐藏音箱（默认，全服可闻，不生成假人）

      audio_volume / audio_loop
          音量与是否循环。

      audio_calls
          音频调用声明表 —— 写明"有哪些音频调用 / 打开后什么效果 /
          通过哪个 API 播放会怎样"。用 EXPAS audio call 可随时打印这份声明。
          第三方插件可调用:
              ExpasApi.PlayAudioFile(file)    播放 audio\file
              ExpasApi.PlayMvpMusic(userId)   播放该玩家命中的第一名音乐盒
              ExpasApi.StopAudio()            停止播放

【6. 自检与排查】
--------------------------------------------------------------------------------
  指令:
      EXPAS mvpmusic list
          列出每个 JS 的  owner → 音频  [文件存在]/[文件缺失]，并列出
          目录里存在但没有任何 JS 引用的音频。
      EXPAS mvpmusic play <玩家ID>
          立刻试播一次（不等到回合结束），用于验收。

  常见问题:
    · 回合结束没响
        → EXPAS mvpmusic list 看有没有该 Steam64 的条目；
          再看是否标了 [文件缺失]；确认 mvp_music_enabled = true
    · 标了 [文件缺失]
        → 音频没放进 mvp_music\，或 audio 里写的文件名（含扩展名）与实际不符
    · 日志 Warn "音乐盒 JS 不可用(缺 owner 或 缺 audio=)"
        → 声明文件里没有 17 位 Steam64，或 audio 键名/值写错
          （键名只认 audio / music / file / path / wav）
    · 中文文件名读不出来 / 乱码
        → 声明文件与音频名都用 UTF-8 无 BOM 保存
    · 玩家不是伤害第一名
        → 音乐盒只在"回合伤害榜第一"时触发；可先用 mvpmusic play 单独验收

  服务器启动/触发时的日志关键字:
      [EXPAS] 音乐盒条目: <Steam64> → <文件>  ← <文件名>
      [EXPAS] 第一名音乐盒触发: <Steam64> → <文件> (来自 <文件名>)
      [EXPAS] 第一名音乐盒音频缺失: …
      [EXPAS] ▶ 音频 <文件> (x.xs) 隐藏音箱播放
